01 / The idea

A task stays the same.
The demands do not.

Reaching an object, making contact, transporting it, and placing it precisely require different perceptual and control behaviors—even within one instruction.

A fixed adaptation update has to serve all of these contexts. MorphAct instead learns a shared rule that maps the current observation, language instruction, and robot state to parameter updates. As the scene changes, the effective policy can change with it.

The distinction appears directly in the policy. At replanning time t, the context is xt = (ot, ℓ, st). MorphAct predicts an action chunk using the base parameters plus an update generated for that context:

The policy, conditioned through its parameters

Y^t=πθ+Δθ(xt)(xt)
θ Base policy parametersΔθ(xt) Generated for the current contextŶt Predicted action chunk

The generator weights are shared across contexts. The updates they produce are context-dependent.

02 / Context to parameters

Generate a small update.
Change the effective model.

MorphAct generates low-rank factors for selected projections in both the vision–language module and the action module.

For a target block j, the generator produces two matrices, Aj,t and Bj,t. Their product defines an additive parameter update. The base weights stay frozen; the factors vary with the current context.

Low-rank factors are generated outputs. The rank rj is defined per target block.

Execution uses the factors directly. For a row-vector input u, the adapted projection is the frozen base output plus a factored residual:

y=uWbase+αjrj(uAj,t)Bj,t

This computes the update without materializing a dense matrix. The same principle applies to both modules, with factor layouts matched to their projection geometry.

Inside each generator, queries identify layers, projections, and rank positions. Generator blocks combine cross-layer attention, within-layer parameter attention, and cross-attention to the context tokens. Separate A/B readouts synthesize the factors for each selected block, preserving token-level conditioning.

Perception shapes action adaptation

Two generators, connected by the representation.

The generation order follows the policy’s computation. The vision–language generator first adapts the representation. The action generator then uses that adapted representation and robot state to generate its own update.

01

Generate the VLM update

Δθv,t=Gv(et;φv)

Image and language embeddings et = E(ot, ℓ) condition the vision–language generator.

02

Compute the adapted representation

(ht,Ct)=Fv(et;θv+Δθv,t)

A single adapted VLM pass produces features ht and native action conditioning Ct.

03

Generate the action update

ua,t=Ca(ht,st;ρa)Δθa,t=Ga(ua,t;φa)

The condition constructor combines adapted features with robot state, connecting upstream adaptation to action-side generation.

In π0 and π0.5, ht consists of final multimodal prefix tokens, while Ct carries the layer-wise prefix key–value states used by the action expert. The generators have separate weights, but the action update depends on what the adapted VLM produces.

03 / Learning the rule

Let the action objective
train both generators.

The generated factors are differentiable intermediate outputs. Both generators learn jointly through the backbone’s native action objective.

The trainable parameters Φ include the two generators, the robot-state projection, and projectors retained as trainable by the adaptation configuration. The remaining backbone parameters stay frozen.

The original action-learning objective

minΦ𝔼(xt,Yt)∼𝒟,ξ[ℒnative(y^Φ(xt,Yt;ξ),Yt;ξ)]

Demonstrations supply xt and Yt. The variable ξ contains the randomness required by the native training objective.

For π0 and π0.5: predict the flow velocity.

A sampled time τ mixes the demonstrated action chunk with noise ε. The model’s training target is the velocity along this action–noise path:

zτ=τε+(1−τ)Ytvtarget=ε−Yt

The adapted representation receives training signals through two routes: its use in native action conditioning, and its use in generating action parameters. This makes the coupling part of the optimization itself.

The first term follows action conditioning. The second follows action-side parameter generation. Both routes remain differentiable; Jy,z = ∂y / ∂z.

04 / Parameters to action

Generate once.
Reuse throughout the chunk.

Adaptation runs at the pace of new observations. The action expert keeps its native prediction procedure.

At each replanning step, MorphAct generates both updates and caches the adapted action condition. All solver evaluations for that action chunk use the same generated parameters. After executing a prefix of the chunk, the next observation triggers a fresh update.

05 / In the real world

Four tasks.
Two arms in the loop.

Bimanual manipulation requires coordinated perception and control as objects move and contacts change.

We demonstrate MorphAct and π0.5 on four tasks that combine grasping, object reorientation, placement, and interaction with a drawer.

01

Letter arrangement

Grasp & orientation. Arrange the letters through a sequence of grasps and changes in orientation.

02

Bottle handling

Grasp & lift. Establish a grasp on the bottle and control its motion during lifting and handling.

03

Object sorting

Sorting & placement. Select objects, transport them, and place them in their destinations.

04

Drawer storage

Handle engagement. Interact with the drawer handle as part of a storage sequence.
